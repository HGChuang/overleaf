# F-L1-02 单因素实验结果

日期：2026-09-08。Run：`f-l1-02-ab-01`。状态：**18 次会话、9 对对照已完成，轨迹审计与逐例复核完成**。

## 结论

追加带权威行号的源码展示字段，在这批固定样本中提高了定位准确性：**两个 caption 行号都准确：A 6/9，B 9/9；成对改善 3、退化 0、持平 6。** 两组均能发现歧义并请求作者选择，没有擅自提交补丁。

结果支持将这一输出形式作为下一步候选改进；不代表已证明普遍可靠，也不代表已经修改或部署生产读取工具。本轮只有 3 种相近的合成场景、各重复 3 次，不能当作 9 个独立真实需求的稳定成功率。

## 实验设置

- A：当前生产 `read_file / read_file_fragment` 返回值。
- B：原返回值仅追加 `lineNumberedContent`，每行显示准确行号和对应源码。原始 `content`、分页边界、源 hash、工具描述和 prompt 不变。
- 两组都保留已完成的 F-L1-01 修复，不混用修复前后版本。
- 原歧义题、固定 LF 前缀题、固定 CRLF 前缀题各 3 对，预先交替 AB/BA 顺序。前缀题明确要求给出准确 caption 行号；原题没有强制。
- 使用 huoshan 的 `deepseek-v4-flash-ga-260731`，温度 0.7，窗口 1,000,000，输出上限 16,000，12 步/300 秒；无总 token 上限。
- 每次独立清空隔离测试数据，成对项目/会话身份一致；不读取旧评测或 Git 历史。

完整预设方案见 [实验方案及接续](copilot-f-l1-02-experiment.md)。

| 两个 caption 的准确行号均给出 | 6/9 | 9/9 |

最后一行采用更严格的精确边界标准：A 中另有两次 caption 正确，但额外给出的 table 范围包含其他文档环境行，或没有对应实际 table 起止。它们没有计为 caption 行号错误。近似位置也与明确断言错误分开记录。

“正确澄清”与“准确定位”是分开的指标：例如前缀 LF 第 3 对的 A 虽然正确请求选择，却未满足用户对准确行号的要求，不能说它完整完成了用户任务。

## 单因素与有效性审计

- 9/9 对的首个实际 HTTP 请求体完全相同，包含模型、prompt、工具 schema 和用户/项目上下文。
- 9/9 对的两组都实际调用了读取工具，实验处理均有机会被模型看到。
- 实际干预事件均只改变新增展示字段，原 `content`、所有其余返回字段和分页边界一致。
- 所有处理后的页仍在 4096 字节预算内，没有因 B 增大结果而触发归档或裁剪，从而引入第二种运行条件。
- 源码指纹在整个实验期间保持不变；A/B 后续工具路径允许自然分化，未强制重放旧响应。
- 独立检查通过：3 项干预测试、18 个任务的工程编译、72 项错误结果负对照、执行器 TypeScript。
- 完整回答逐条与源文件核对，无模型裁判。复核保留回答 SHA256，原自动判定文件不回写。

此处的“单因素”是**有无新增带行号展示字段**这一工程改动。B 同时重复展示了一份源码，故本实验没有分离数字标注本身与源码重复展示的心理/注意力效应。如果要进一步解释内部机制，可另设无行号副本对照；本轮不据中间结果临时增加组别。

## 建议下一步

1. 将带行号源码展示作为候选生产改进，保持可复制的原始 `content`；不改 prompt，也不让模型自行维护行号。
2. 正式接入前必须把新增字段纳入 `sourcePage` 总字节预算，验证长行、CRLF、UTF-8 中间分页、无漏字/重复字和引用位置。当前实验适配器只对小页追加字段，超预算会报实验无效，不宜直接原样上线。
3. 验证它不会干扰 `submit_patch` 的原文复制，并复测只读定位、L1-02/L1-11 编辑、L1-12 分页任务。扩大到不同模板后再决定是否默认开启。

本轮没有修改生产读取逻辑。F-L1-01 的权威提案回执修复保持原样。
