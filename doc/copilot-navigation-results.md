# 归档导航单因素实验

后续更新：本文件记录的是未采用的描述改写实验；后来按文件名定位历史回执的接口方案已验证并接入，见 [后续结果](copilot-navigation-source-results.md)。

## 要回答的问题

此前 checkpoint 已给出目标工具回执的绝对消息索引，但模型仍从消息 0 浏览。检验是否仅用更明确的 read_context_history 描述，就能减少无关读取，并保持任务完成和证据完整。不是修改页长、增加工具、删除历史或提高步数上限。

A 为当前生产描述；B 强调按 toolLedger.resultMessage 直达、仅在所需证据未出现时续页、缺定位或任务需要才浏览其他消息。9 对、18 会话，三个布局各重复三次，AB/BA 顺序交替。每对相同 source/prompt/ID/确定性生产 checkpoint；生产随机摘要的完整路径留给采用后的回归。

## 判定与局限

必须实际从目标回执恢复 FINAL CAPTION，正确候选通过保护字节与独立编译。无关读取指非目标消息读取；这些固定任务没有要求浏览其他历史，不能将此指标直接推广到需要多证据综合的任务。目标证据续页不算无用。重复页也单独记录。首个实际 HTTP 请求必须仅工具描述不同，原始 seed 必须完全一致。

实际观测到同一任务重复时 A 有时直接找到目标，B 也可能增加 todo 等其他步骤，所以最终看全配对总量和每对分布，不宣称每次调用都更省。无随机种子保证；小样本合成开发集不能代表线上成功率。

两轮均已完成独立审计，过程见 copilot-navigation-progress.md。
