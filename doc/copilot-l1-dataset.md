## 判定边界

- 9 个编辑任务均由独立编译器验证最终交付候选；其中两道修复题还要求 agent 自行调用编译工具验证该 patchId。
- 受保护区按字节检查。这些题明确要求保留其余源码，因此未要求的格式化也不通过。不是用此标准评判一般自由写作。
- 修复题允许预先列出的等价加粗形式或环境间空白差异；不强求 hunk 的锚点或分割方式等于参考补丁。
- 只读/澄清三题的正则只作初筛，最终保留原文进行证据复核。所有题均需复核“已提出/已验证/已应用”的报告与回执是否一致，自动检查通过不直接等于任务通过。
- L1-08 刻意采用可确定判定的编辑要求，不声称覆盖开放式段落改写质量。
- 这批题不覆盖多轮接受/拒绝、实际协作修改、长期压缩或真实需求频率；后续按 L2 和扩充任务集单独验证。

## 先检验题目，再检验 agent

预检逐题执行：初始项目编译结果符合预期；参考解实际编译成功；保护区修改、删除文件、不作目标修改等负对照被拒绝。编辑题另通过生产 SnapshotStore/GridFS、补丁与编译控制器及真实 HTTP client，验证参考候选可以持久化并编译。

首轮运行前冻结题目、代码与配置 SHA256；后续更改不得覆盖已冻结的同名 run。
